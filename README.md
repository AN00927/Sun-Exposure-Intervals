# Vitamin D Scheduling Optimization Model

Repository for a vitamin D / UV exposure scheduling model with photoadaptation,
validation scripts, evidence cards, and generated analysis outputs.

## Overview

The code models serum 25(OH)D, melanin, and stratum corneum dynamics under UV
exposure schedules. It is organized around the practical scheduling questions
in `vitd_objectives.py`, not around the retired per-SED ratio metrics.

Validation status and interpretation: see `MODEL_AND_EVIDENCE.md`
('Validation status'); raw numbers: `RESULTS.md`.

## Quick Start

```bash
pip install -r requirements.txt
PYTHONIOENCODING=utf-8 python3 run_all.py
python3 -m pytest
```

On Windows, `PYTHONIOENCODING=utf-8` matters because the generated reports use
Unicode characters.

## Repository Layout

- `vitd_model.py`: model state, parameters, source calibration, and canonical
   parameter values.
- `vitd_objectives.py`: the decision problems and schedule objectives.
- `vitd_protocols.py`: named protocol helpers for study-specific simulations.
- `vitd_validation.py`: validation suite wiring.
- `scripts/`: standalone analyses, sweeps, and diagnostics.
- `tables/` and `figs/`: generated outputs from the latest analyses.
- `audit_outputs/`: extracted datasets, summaries, and provenance artifacts.
- `paper/`: manuscript skeleton and paper-specific notes.

## Key Outputs

- `RESULTS.md` is auto-generated by `run_all.py` and captures the latest
   validation and analysis summary.
- `MODEL_AND_EVIDENCE.md` is the single canonical document: model description,
   validation status, problem statement, evidence cards, and open work /
   assumptions / changelog.

## Running The Main Analysis

Run the full pipeline to regenerate the summary report, tables, and figures:

```bash
PYTHONIOENCODING=utf-8 python3 run_all.py
```

Run the tests only:

```bash
python3 -m pytest
```

## Documentation Map

- Start with `MODEL_AND_EVIDENCE.md` - the canonical document: problem
   statement, model, validation, evidence, and open work.
- Start with `paper/README.md` for the manuscript status and what is drafted
   versus stubbed.

`RESULTS.md` carries the latest generated output; `CLAUDE.md` documents repo
conventions.

## Notes

- Parameter values live in one place: the `vitd_model.py` module docstring.
- Generated reports may be overwritten by the next pipeline run.
- For a concise view of the current validation state, use `RESULTS.md`; for a
   more narrative interpretation, use `MODEL_AND_EVIDENCE.md`.
